## Goal

Give team ratings a first-class, enforceable position in the weekly operating lifecycle (`close` → `prepare` → `publish` → `freeze` → `score`).

Specifically:
1. Prevent the pipeline from preparing or publishing predictions based on stale or missing team ratings by hard-failing `prepare-week` if ratings do not cover all completed games prior to the target week's `as_of` cutoff.
2. Require exact rating provenance (`rating_manifest_sha256`) on V5 prediction runs in the serving database while preserving future V4 rollback publishing.
3. Formalize the operational contract and sequence between the ratings refresh chain (`repair` → `measurements` → `rating replay` → `project-v5-ratings`) and the weekly game lifecycle in documentation.

## Current State

- The week lifecycle (`close-week` → `prepare-week` → `readiness` → `publish-week` / `publish-replay-week` → `freeze-week` → `score-week` / `score-replay-week`) is managed by `src/cks_picks_cfb/ops/` and `scripts/pipeline/`.
- Ratings are generated by an independent multi-stage chain:
  1. Data repair (`scripts/data/verify_repaired_corpus.py` / `data_first_phase2d`)
  2. Football measurements (`scripts/ratings/generate_measurements.py`)
  3. Rating replay (`scripts/ratings/replay_possession_ratings.py`)
  4. Projection to Neon (`scripts/pipeline/publish_v5_ratings.py` via ops command `project-v5-ratings`)
- `prepare-week` in `src/cks_picks_cfb/ops/__main__.py` (and validation via `scripts/pipeline/check_prepared_week.py`) verifies schedule games, scores, and Gold feature table coverage, but performs **zero checks** on whether ratings are fresh or exist in the serving database for the target week.
- `prediction_runs.rating_manifest_sha256` was introduced in migration `0013_v5_public_selection.sql` as a nullable column. While V5 prediction runs populate this column, the database does not enforce its presence for new runs.
- The web application and model forecast both depend on team ratings (e.g. `v5_rating_snapshots` in Neon). If an operator runs `prepare-week` without first refreshing and projecting ratings, predictions risk running against stale ratings without a hard pipeline error.

## Proposed Approach

1. **Gate `prepare-week` on Rating Currency:**
   - In `scripts/pipeline/check_prepared_week.py` (invoked by `prepare-week` step `target_week_readiness`), select one projected rating generation from `v5_rating_snapshots` for the target season with cutoff no later than `as_of`. Current row `week` is each team's most recent game week, so admit rows with `week < target week` and group by shared manifest and cutoff. Require current rows for target teams with completed games and same-generation preseason rows for teams without completed games.
   - If the generation is absent, ambiguous, incomplete, or older than the latest completed kickoff plus the existing six-hour rating availability buffer, `prepare-week` hard-fails with an actionable error. Database errors fail closed; there is no offline bypass.
   - For Week 0 / preseason, ratings must cover the preseason baseline.

2. **Enforce Rating Provenance in Database Contract:**
   - Add append-only migration `contracts/migrations/0017_require_rating_manifest.sql`.
   - Add a CHECK constraint on `prediction_runs` that requires `rating_manifest_sha256 IS NOT NULL` when `model_id LIKE 'v5-%'`. The existing column constraint enforces 64 characters. V4 and legacy rows retain nullable provenance.
   - Update contracts in `contracts/schema.sql` and `contracts/schema.ts` (and synchronize `web/src/lib/schema.ts` per contract check).

3. **Operational Documentation & Runbook Integration:**
   - Update `docs/ops/weekly_pipeline.md` and `docs/ops/production_runbook.md` to document the exact sequence:
     `close-week (N-1)` → **Ratings Refresh & `project-v5-ratings`** → `prepare-week (N)` → `readiness` → `publish-week (N)`.
   - Specify timeline labels for rating generations (e.g. `preseason`, `post-week 0`, `post-week 1`, `post-week 2`, etc.).

### Task 1 — Rating Currency Gate in `prepare-week`

**Files:**
- `scripts/pipeline/check_prepared_week.py`
- `src/cks_picks_cfb/ops/__main__.py`

**Changes:**
- Update `scripts/pipeline/check_prepared_week.py` to:
  1. Resolve the database URL from the existing explicit `--environment` and runtime-target environment variables. Do not place credentials in subprocess arguments or persisted step definitions. A connection failure blocks readiness.
  2. Select the latest eligible `current` generation for the target season by cutoff using rows whose last-played `week < target week`; fail on tied or mixed manifest identities. For preseason with no completed games, select a complete `pregame` baseline.
  3. Require same-generation `current` snapshots for target teams with completed games and `pregame` preseason snapshots for target teams without them. Require the generation cutoff to be at least six hours after the latest completed kickoff before `as_of` and no later than `as_of`.
  4. If ratings are missing or stale, exit nonzero with a descriptive message:
     `"Ratings are stale: latest rating snapshot cutoff is {rating_cutoff}, but games completed as of {last_game_time}. Refresh ratings and run project-v5-ratings before prepare-week."`
  5. Include ratings currency info in the JSON summary output (`rating_cutoff_utc`, `rating_manifest_sha256`).
- Verify `src/cks_picks_cfb/ops/__main__.py` already passes the explicit environment and resolved runtime target to the child process; change it only if that wiring is insufficient.

**Acceptance criteria:**
- `check_prepared_week.py` exits 0 when one complete generation covers all completed games prior to `as_of`.
- `check_prepared_week.py` exits non-zero with informative error when ratings are missing or older than the latest completed game.
- `prepare-week` aborts before producing ready state if ratings are stale.

## Risks and Edge Cases

- **Offline / Local Dev Mode:** Production readiness fails closed without the database. Unit tests inject database responses without adding a runtime bypass.
- **Mid-week Games / Bye Weeks:** The `as_of` timestamp bounds completed games using the canonical `kickoff_utc < as_of`, not a Saturday assumption.
- **Zero-game Periods (Preseason):** For Week 0 / Week 1 before games have completed, a complete `pregame` preseason baseline with cutoff no later than `as_of` is accepted.

## Approved amendment — 2026-09-27

The user approved this revised contract after Sol identified a material conflict in the Draft: a fixed September 27 cutoff would constrain existing and future V4 runs, and the draft left the offline bypass and rating generation selection undecided. The V5-only CHECK, single-generation currency test, fail-closed database behavior, and six-hour availability boundary above replace those Draft alternatives. This task authors migration 0017 but does not apply it or activate a prospective run on a live branch. Live-branch audit and the Week 5 read-only check depend on accessible branch credentials.

Implementation discovery: Preview's verified Week 5 source projects `current` rows with team-specific last-played weeks 2–4 under one manifest and cutoff. The condition `week = target week` from the initial code attempt would falsely reject it. The approved generation-by-manifest intent is implemented with `week < target week` instead. Silver schedule rows use provider aliases for six target teams, while projected ratings use `canonical_team`; the gate applies the existing mapping before comparing coverage. The read-only Week 5 check passed with 215 completed games, 56 target games, cutoff `2026-09-27T14:15:00Z`, and rating manifest SHA `75e016e1b9876c940cdc98d70aebcc01472b9b1fd160ca6e8e1358d87208cae0`. Preview and production V5 provenance audits found no missing SHA rows (21 and 16 V5 rows, respectively). Migration 0017 was not applied to either live branch in this task.
