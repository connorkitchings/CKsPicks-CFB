## Context and Decisions
- Root cause of the perceived change: the ratings source pin follows the latest selected run. Selecting Week 5 flipped it from the 09-22 to the 09-27 generation, so the "Post-Week 3" tab silently served post-Week 4 rows. Immutability held; labeling lied.
- First attempt (post-4 enum + frozen post-3) fixed the symptom but perpetuated the disease — every new week would need another hardcoded period. Scrapped per user direction.
- Final semantics in `getWeeklyRatings`: exact cutoff id → that generation's frozen rows (latest per team, no source pin); "current"/empty/retired week-style params (`post-N`, `week-N`, bare numbers) → newest generation via source-pinned `getCurrentRatings`; `preseason` unchanged. Retired params resolve to latest with a matching label rather than a week table.
- `getRatingPeriods` lists distinct frozen `current` cutoffs (desc) plus preseason; the page timeline renders it directly, so Week 6+ needs zero web changes.
